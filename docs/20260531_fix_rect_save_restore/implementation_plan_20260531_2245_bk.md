# 実装計画書：アライメント矩形位置情報の保存・復元バグの修正

アコーディオン上で調整した「総合力」や「カテゴリー数値（SHO数値、PAS数値等）」の個別調整値（個別シフト / 個別スケール）がJSONに正しく保存されず、復元できない致命的なバグの原因を調査し、これを確実に解消するための実装計画です。

---

## 原因分析

`app.py` 内の Python-JS 間における状態同期処理（`update_state` および `trigger_analysis`）において、個別パラメータの同期対象リスト `detail_items` を動的に生成する際、**「総合力」および大項目カテゴリー数値（「SHO数値」「PAS数値」「DRB数値」「DEF数値」「PHY数値」「SPD数値」）**がリストから完全に漏れていました。

そのため、ユーザーがアコーディオン上でこれらの個別微調整（スライダー操作）をいくら行っても、JavaScript側から返された最新データが Python 側の `st.session_state` に同期されず、初期値である `[0, 0]` （スケールは `[1.0, 1.0]`）のままとなっていました。その結果、JSONファイルにエクスポートする際も初期値のまま書き出され、復元できないバグが発生していました。

---

## 対策案（提案内容）

本バグを構造的に100%封殺するため、以下の改修を実施します。

1. **セッション初期化の完全網羅（GK項目の事前定義）**:
   `app.py` で `st.session_state.individual_offsets` および `st.session_state.individual_scales` を初期化する際、`DEFAULT_ROIS` に定義された全項目に加え、GKロール特有 of 置換項目（`セービング`, `反応速度`, `1対1`）も初期値リストに完全網羅し、キーエラーや漏れを事前に防止します。

2. **フィルタリングの廃止と安全な自動同期**:
   JS側からの状態同期処理（`update_state` および `trigger_analysis`）において、制限リスト `detail_items` によるフィルタリングを廃止します。
   `DEFAULT_ROIS` のキーとGK項目を合わせた全項目リストをループ処理し、JS側から受け取ったデータに該当キーが存在する場合に安全かつ動的に `st.session_state` に同期する構造へと刷新します。

3. **ローカル復元処理の堅牢化（フォールバック付き復元）**:
   ローカルJSONファイルをアップロードして復元する際、キーが欠落している場合でもクラッシュせず安全に復元できるよう、全項目に対してデフォルト値（オフセット `[0, 0]`, スケール `[1.0, 1.0]`）で補完しながら辞書を再構築するロジックを導入します。

## 検証計画

### 1. 自動コンパイル検証
- 修正後の `app.py` が Python のコンパイルエラーを起こさないことを確認します。
  ```powershell
  python -m py_compile app.py
  ```

### 2. 手動による機能動作検証
1. **スライダー操作とJSON保存**:
   - アプリケーションを起動し、プレビュー画像（テスト画像）を表示します。
   - 「SHO数値」や「PAS数値」などの大項目数値の個別調整スライダーを動かします（例: Xシフトを -5px、Yシフトを +3px など）。
   - 「決定力」や「ショートパス」などの詳細数値項目も適当に調整します。
   - 「ローカルに保存 (JSON)」ボタンを押下して `sakatsuku_alignment.json` をダウンロードします。
   - ダウンロードしたJSONを開き、`individual_offsets` の中に `"SHO数値"` や `"PAS数値"` が動かした値（非ゼロ）で保存されていることを確認します。
2. **JSONからの完全復元**:
   - 画面を一度リロードして初期状態（すべてのスライダーが 0 または 1.00）に戻します。
   - 「ローカルから復元」でダウンロードしたJSONファイルをアップロードします。
   - アップロード後、画面上のスライダーおよびプレビューのHUD枠線が、保存前と寸分違わず完全に復元されることを確認します。
