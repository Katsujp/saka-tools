# 実装計画書：アライメント矩形位置情報の保存・復元バグの修正（最終根本解決版）

スライダーでの調整結果がJSONファイルに一切保存されず、復元も機能しなかった問題の「真の根本原因」を完全に特定し、二度と再発しないように完全に根絶するための実装計画です。

## 🔍 原因分析

本不具合の真の物理的原因は、フロントエンド（JavaScript側）における**「動的HTML生成によるイベントリスナーの剥落」**および**「イベント通知漏れ」**にありました。

1. **動的生成スライダーにおけるイベントリスナーの剥落（値が保存されない最大の原因）**:
   アコーディオン内の個別微調整スライダー（「走力」や「ジャンプ」を含むすべての個別スライダー）は、チェックボックスのON/OFFやデータの逆同期のたびに、JS側で `setupAlignmentUI()` が走り、`innerHTML` による文字列代入で動的に再生成されます。
   この動的な `innerHTML` の代入により、ページロード時に登録されていた `document.querySelectorAll(".apple-slider").forEach(...)` による `change` イベントリスナー（`notifyStateChange` を呼び出すトリガー）が**完全に剥がれ落ちて消失**していました。
   そのため、アコーディオン内のスライダーをいくら操作しても `notifyStateChange`（親フレーム Streamlit への同期処理）が1ミリも実行されず、Python側のセッション状態が初期値 `[0, 0]` （スケールは `[1.0, 1.0]`）のまま固定されてしまい、JSONへの書き出しも初期値のままになっていました。

2. **全体アライメントスライダーにおけるイベント通知の欠落**:
   静的な全体アライメント調整スライダー（全体X/Yシフト、全体X/Yスケール）の HTML 定義に、インラインの `onchange="notifyStateChange()"` が記述されていませんでした。そのため、何らかのタイミングでイベントリスナーが外れると、全体スライダーの操作も親へ通知されなくなっていました。

3. **JS側の配列型チェック（`Array.isArray`）の欠如による不安定さ**:
   逆同期処理の中で `args.active_items` や `lastSentInd` などのオブジェクトが配列であることを前提としたプロパティアクセス（`.length` や `[0]`）があり、型不一致が発生した際に `TypeError` で処理がクラッシュする潜在的リスクが存在しました。

---

## 🛠️ 対策案（提案内容）

動的生成に起因するイベント剥落を物理的・構造的に100%排除し、スライダーのすべての変更を確実に親（Python）へ伝播させるため、以下の極めて堅牢な改修を実施します。

1. **「イベントデリゲーション」の導入（物理的解決）**:
   動的に再生成される個別スライダーに個々にリスナーを貼るのをやめ、`document.body.addEventListener("change", ...)` によるイベントデリゲーションを導入します。
   JavaScriptのイベントバブリングの仕組みを利用し、アコーディオンが何度動的に再作成されても、親である `body` 要素が一括してスライダーの `change` イベントを100%確実にキャッチして `notifyStateChange()` を実行します。これでリスナー剥がれのバグを完全根絶します。

2. **静的全体スライダーへのインライン `onchange` の完全追加**:
   静的HTMLに記述されている4つの全体アライメントスライダー（全体X/Yシフト、全体X/Yスケール）に、明示的に `onchange="notifyStateChange()"` を追記し、2重の防護策とします。

3. **`Array.isArray` による防弾仕様の型チェックの徹底**:
   逆同期処理で配列のプロパティや添字（`[0]`, `[1]`）にアクセスするすべての箇所に、`Array.isArray(x) && x.length >= 2` などの防弾仕様の型ガードを追加し、不安定なデータが降ってきた場合でも絶対にクラッシュしない構造にします。
