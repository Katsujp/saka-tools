# 実装計画書：アライメント保存・復元バグの修正 ＆ グレーアウト点滅の解消

スライダーの調整値が保存・復元できないバグの核心（イベントリスナー剥落）を治療する対応に加え、キーボードでの微調整（矢印キー連打）時に画面全体がグレーアウトして点滅してしまう不快な現象を完全に解消するための実装計画です。

---

## 🔍 原因分析

### 1. 保存・復元が機能しない真の物理的原因 (再掲)
- **イベントリスナーの剥落**: アコーディオン内の個別スライダーは、チェックON/OFFや逆同期のたびに `setupAlignmentUI()` によって `innerHTML` を使い動的に再生成されます。これにより、ページロード時に登録されていた `change` イベントリスナー（Pythonへの同期トリガー）が**完全に剥がれ落ちて消失**していました。そのため、スライダーをいくら動かしても値が親に送信されず、JSONが初期値 `0` のままになっていました。

### 2. キーボード連打時に画面がグレーアウトする原因
- **Streamlit デフォルトのロード中オーバーレイ**: キーボードの矢印キーでスライダーを細かく連打すると、連打するたびに `change` イベントが発生し、Python 側の再実行（Running）が非常に短い間隔で連続してトリガーされます。
  Streamlit の仕様として、スクリプト実行中はユーザーの誤入力を防ぐために**画面全体の要素を半透明（`opacity: 0.2` 等）にして非活性化（グレーアウト）する半透明オーバーレイ**が適用されます。連打するとこのオーバーレイが高速でON/OFFされるため、画面が激しく点滅して極めて見づらくなっていました。

---

## 🛠️ 対策案（提案内容）

バグ治療とグレーアウトの解消を同時に行い、プレミアムな極上の操作感（UX）を実現するため、以下の改修を行います。

1. **「イベントデリゲーション」の導入（バグの根本解決）**:
   個別のスライダーにリスナーを貼るのをやめ、`document.body.addEventListener("change", ...)` によるイベントデリゲーションを導入します。
   JavaScriptのイベントバブリングの仕組みを利用し、アコーディオンが何度動的に再作成されようとも、親である `body` 要素が一括してスライダーの `change` イベントを100%確実にキャッチして `notifyStateChange()` を実行します。これでリスナー剥がれのバグを完全根絶します。

2. **「150ms デバウンス同期」の導入 (連打によるリランの抑制)**:
   JS側の `notifyStateChange` に **150ms のデバウンス（遅延同期）** を組み込みます。
   キーボードの矢印キーを押しっぱなしにしたり連打している間は、値の送信を保留し、**連打の手が止まった瞬間（最後のキー入力から150ms経過後）に初めてスマートに Python 側へ同期**させます。これにより、微調整中の怒涛の再実行（Run）によるブラウザへの過度な負荷とチラつきを根絶します。

3. **Streamlit グレーアウトフェードの「CSSによる強制無効化」**:
   `app.py` のスタイリング部分に、再実行中に適用される不透明度の変化（`opacity` 減少）を無効化するCSSを追加します。
   ```css
   /* 再実行中（Running）のフェード効果を完全に抹殺して常にクッキリ表示 */
   [data-testid="stAppViewContainer"] [data-testid="stBlock"],
   div.element-container,
   iframe {
       opacity: 1 !important;
       transition: none !important;
   }
   ```
   これにより、万が一バックグラウンドで処理が走った際でも、画面は一切グレーアウトせず、常に完全にクッキリと表示され続けます。
