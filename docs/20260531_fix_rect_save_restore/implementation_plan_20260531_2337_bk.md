# 実装計画書：解析実行ボタンフリーズ不具合の解消 ＆ 重複排除メッセージング設計への刷新

「ローカルから復元」でアライメントを復元した後に「解析を実行」ボタンをクリックしても解析が動かない不具合を解消し、動作の安定性と再実行性を完璧に担保するための実装計画です。

---

## 🔍 原因分析

### 1. 解析を実行ボタンが動かなくなる真の物理的原因（OCR再実行ガードの永続化）
- **Streamlit カスタムコンポーネントのメッセージ再評価仕様**:
  Streamlit のカスタムコンポーネントは、Python 側のスクリプトが再実行されるたびに、直近で JS 側から送信されたデータ（`trigger_analysis` メッセージなど）を返し続けます。これをそのまま無条件に処理すると、解析実行による画面更新で Python が再実行されるたびに解析が何度もトリガーされ、無限ループが発生します。
- **不完全な「完了状態ガード（`ocr_run_completed`）」**:
  無限ループを防ぐため、Python 側では解析が1度完了すると `st.session_state.ocr_run_completed = True` に設定し、`trigger_analysis` メッセージが来ても解析を実行しないようにガードしていました。
  しかし、このガードは「スライダーを操作して JS 側から `update_state` メッセージが届き、ガードが `False` にクリアされる」まで**永続的に解除されません**。
- **不具合が発生した具体的事例**:
  1. **JSON復元直後の実行フリーズ**: JSONファイルをアップロードして復元した際、Python 側の `st.session_state.ocr_run_completed` は `True`（または初期状態のまま）になっており、かつスライダー操作が発生していないためガードが解除されず、ボタンを押しても解析が一切走りません。
  2. **同位置での再解析フリーズ**: 一度解析を実行した後に、アライメント位置を動かさずに画像だけを切り替えたり、もう一度やり直すために「解析を実行」ボタンを押した場合、ガードが解除されていないためボタンが完全にフリーズしたように見えます。

---

## 🛠️ 対策案（提案内容）

「状態（完了フラグ）」に依存する脆弱なガード設計を廃止し、Streamlitの通信設計として最も堅牢でプロフェッショナルな**「メッセージ重複排除（Deduplication）設計」**へと刷新します。

### 1. JS側での一意の「メッセージID（`msg_id`）」の付与
- JSコンポーネントから `sendMessage` を送信する際、自動的にミリ秒タイムスタンプとランダム文字列を組み合わせた一意の `msg_id` をペイロードに付与します。
  ```javascript
  function sendMessage(type, data) {
      const payload = { 
          type: type, 
          data: data,
          msg_id: Date.now() + "_" + Math.random().toString(36).substring(2, 9)
      };
      sendControlMessage("streamlit:setComponentValue", { value: payload });
  }
  ```
- これにより、ユーザーがボタンをクリックしたり、スライダーを操作するたびに、必ず新しい `msg_id` を持ったメッセージが発行されます。Python再実行によって「前回と同じメッセージ」が返ってきた場合は、`msg_id` が完全に同一になります。

### 2. Python側での「重複排除ガード」の実装
- Python 側で `hud_response` を受け取った際、`msg_id` をチェックし、すでに処理済みの `last_processed_msg_id` と一致する場合は処理を無視します。
- メッセージが新しい `msg_id` を持っている場合のみ処理を実行し、`last_processed_msg_id` を更新します。
- これにより、`trigger_analysis` が発生した際、「それが新しいボタンクリックイベントである（新しい `msg_id` である）」ときは、以前の完了状態に関わらず**無条件で確実に解析をトリガー**できます。無限ループの心配は一切ありません。

### 3. 「ローカルから復元」時の完了状態・メッセージIDの完全リセット
- JSONファイルから設定を復元したタイミングで、Python 側にて `ocr_run_completed = False` および `last_processed_msg_id = None` に明示的に初期化します。
- これにより、復元直後にスライダーを動かさずに「解析を実行」を押した場合でも、確実に解析処理が起動します。

   - 再度解析処理が正常に起動し、結果テーブルが更新されることを確認します。
3. **無限ループ防止の確認**:
   - 解析実行後、画面の更新およびスクリプトの再実行（Running）が完了した際、解析が自動的に2重・3重に実行される無限ループが一切発生しないことを確認します。
