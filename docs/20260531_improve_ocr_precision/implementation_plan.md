# 実装計画：OCR読み取り精度の劇的向上（ノイズ排除とアルゴリズム改修）

## 🚨 エラーの原因究明および要因の検討 (バグ診断)

添付画像1（調整画面）と添付画像2（超速コピペステーションの結果）を照らし合わせ、プログラムの読み取りロジックを調査した結果、**極めて明確な3つの要因**が判明いたしました。

### 1. 【要因1】個別能力値のクロップ範囲（ROI）が広すぎることによる「日本語項目名」の混入
*   **原因**: 
    現在、個別能力値（決定力など）のデフォルトROI座標は `(730, 453, 170, 38)` となっており、**横幅が 170px もある非常に広い領域**を切り取っています。
    これにより、数値部分（541など）だけでなく、左側にある**「決定力」という日本語項目名、および極小の英語略称（Finなど）がクロップ画像の中に丸ごと混入**してしまっています。
*   **誤読のメカニズム**:
    `ocr_engine.py` では、個別能力値を読み取る際に**英語モデル**を使用し、さらに検出された最初のテキスト（`ocr_results[0]`）のみを結果として採用するロジックになっています。
    クロップ画像の中に日本語（「決定力」など）が入っていると、英語モデルがそれを無理やり英数字として解釈しようとし、**「決定力」の文字パーツを「12」や「13534」などと大誤読して `ocr_results[0]` に格納**してしまいます。
    その結果、本物の数値（541など）は無視されるか、あるいはノイズとみなされて空欄になっていました。
    （※「キック力 536」が「12」、「ロングパス 449」が「13534」、「ジャンプ 329」が「4」と誤読されたのは、日本語テキストの誤読そのものが原因です）

### 2. 【要因2】カテゴリー数値への「左側の巨大ランク文字」のめり込み
*   **原因**: 
    「SHO数値」などのカテゴリー数値のROIは `(820, 285, 115, 85)` となっています。
    添付画像1を見ると、数値（1609）の左側には、非常に巨大なランク文字（BやD+など）とそれを囲むバッジ枠が存在します。
    ユーザーが全体アライメントを合わせた際、微小なトリミングズレによって、この**巨大なランク文字「B」や「D+」およびバッジの枠線が数値領域に少しでも侵入すると、EasyOCRが「+」や「D」と数値をひと繋がりのオブジェクトとして検出してしまい**、`allowlist`（数字のみ）の制限によって数字ごと消去され、結果が完全に空欄（全滅）になっていました。

### 3. 【要因3】背景メーターや下線のノイズ干渉
*   **原因**: 
    個別能力値の数値のすぐ下には、緑色や黄色のメーターバーと白い境界線が存在します。
    現在、個別能力値は「二値化なしの生グレースケール」でOCRにかけているため、これらのメーターや下線が数字の文字輪郭と癒合してしまい、OCRエンジンが数字の形状を正確に捉えられなくなっています。

## 🛠️ 提案する具体的な改修方法 (承認後に実施)

これらの問題を完全に封殺し、100%に近い極上の読み取り精度を実現するため、以下の**3つのアプローチを統合した高度な改修**を行います。

### 案1：ROI座標の徹底的なタイト化（数値の厳密な隔離）
余計な「日本語ラベル」「英語略称」「左側ランク文字」「メーターバー」がクロップ領域に物理的に1pxも混入しないよう、デフォルトのROI座標を**「純粋な数値が描画されている中央の狭い領域」だけに極限までタイト化（縮小・隔離）**します。

*   **個別能力値（例：決定力）**:
    *   幅（Width）を `170px` ➔ `65px` に大幅縮小し、X座標を右側にずらす（日本語文字や英語略称を完全にフレームアウトさせる）。
    *   高さ（Height）を `38px` ➔ `25px` に縮小し、下部のメーターを完全に排除する。
*   **カテゴリー数値（例：SHO数値）**:
    *   幅（Width）を `115px` ➔ `75px` に縮小し、X座標を右側に寄せることで、左側の巨大ランク文字「B」「D+」を100%遮断する。

### 案2：個別能力値への「絶対二値化」適用と前処理の最適化
*   `ocr_engine.py` の個別能力値の処理において、生グレースケール拡大処理から、適切な閾値による**絶対二値化（白背景に黒文字化）**へと移行します。これにより、背景メーターのカラーや枠線を完全に消去し、純粋な数値の輪郭のみをクッキリと浮き上がらせます。

### 案3：OCR文字列抽出アルゴリズムの堅牢化（最重要・ノーミス化）
従来の「最初の検出テキスト（`ocr_results[0]`）のみを決め打ちで採用する」という極めて脆弱なロジックを廃止し、**「正当な数値自動抽出アルゴリズム」**へと改修します。

*   **新アルゴリズムの流れ**:
    1. クロップ画像から検出された**すべてのテキスト要素**（`ocr_results` のリスト全体）をループ処理します。
    2. 各テキストから不要な文字を除去して数値化を試みます。
    3. **「最初に数値として正しく変換できた3桁または4桁の正当な範囲の数値（例：100〜9999）」**が見つかった時点で、それを本物のパラメータ数値として採用し、ループを抜けます。
*   **この改修のメリット**:
    *   万が一、周囲の極小文字（例：Fin, Powなど）やメーターのノイズを誤って別オブジェクトとして認識してしまっても、**それらを自動的に完全にスルーし、本物の数値（541など）だけをピンポイントで100%確実に抽出すること**が可能になります。
