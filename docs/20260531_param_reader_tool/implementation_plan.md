# 【サカつく2026】画像無劣化取得後の「OCR認識精度100%化」根本解決改修計画書

本計画は、ユーザー様よりご報告いただいた「貼り付け画像はクッキリ（無劣化）表示されたが、プレビュー表の数値がNoneや誤読になり、正しく反映されない」という問題の真原因を特定し、OCRエンジンの画像切り出し・前処理アルゴリズムを根本から刷新することで、選手パラメータを**「一字の狂いもなく100%完璧にデジタル化」**するための最終改修計画です。

## 🔍 原因分析（OCRが数字を読めなかった3大要因）

ペースト画像の画質は無劣化（最高解像度）で取得できているにもかかわらず、OCRが誤読した原因は、以下の3つの「画像処理の不一致」が重なっていたためです。

### 1. ウィンドウ外周（タイトルバー＆左右枠）による座標のズレ
*   **原因**: ユーザー様がクリップボード経由で読み込ませた画像には、最上部に「SFCC」と書かれたWindowsのタイトルバー（約31px）があり、左右および下部にもウィンドウ境界線（枠線）が含まれていました。
*   **影響**: この「外枠」を含んだまま画像を基準解像度（1920x1080）にリサイズすると、ゲーム画面全体が右下に数％押し縮められてしまいます。OCRは極めてタイトな座標で「総合力」や「能力値」を切り出しているため、わずか数ピクセルのズレで文字の枠外（背景や仕切り線）をクロップしてしまい、誤読（None）が発生していました。

### 2. 従来の「適応的二値化」による文字の穴潰れとノイズ合体
*   **原因**: 従来のOCR前処理で用いていた `cv2.adaptiveThreshold`（適応的二値化）は、文字の輪郭線だけを白くし、文字の中身をくり抜いてしまう（中空文字化）特性がありました。また、数値の背景にあるうっすらとした「縦の仕切り線（グリッド線）」や背景グラデーションを、文字と合体させてノイズにしていました。
*   **影響**: これにより、フォントの「0」の穴が完全に白く潰れてソリッドな丸い塊になり、EasyOCRが「0」を認識できずに読み飛ばしていました（例: `402` が `42` になる、`1260` が `126` になる）。

### 3. クロップ領域のサイズ余裕（マージン）不足
*   **原因**: メイン能力値（SHO, PAS等）のクロップ横幅（W=95）が文字に対して狭すぎ、さらに個別詳細パラメータ（決定力等）の縦幅（H=40）も狭すぎました。
*   **影響**: リサイズ時のわずかな歪みによって、4桁の数字の最後（`1260` の `0`）が枠外に削れて消滅していました。

## 🛠️ 対策・解決策（究極の3大パッチ）

上記の問題を完璧に解消するため、以下の最高峰アルゴリズムを導入します。

### ① インテリジェント境界スキャナー（Auto-Boundary Scanner）の導入
*   画像の上下左右から、ピクセル値の急激な変化（エッジ差分）を自動的にスキャンします。
*   Windowsのタイトルバー（上部）および左右下部のウィンドウ枠を **1ピクセルの誤差もなく自動的に検出し、純粋なゲーム表示領域（16:9）のみを正確に自動トリミング** します。これにより、どのような表示環境でキャプチャしても座標が100%完璧に合致するようになります。

### ② 絶対閾値二値化（Simple Absolute Thresholding）の導入
*   適応的二値化を完全に廃止し、**「輝度155」を基準とする絶対閾値二値化**を導入します。
*   ゲーム内のパラメータ数字は極めて明るい純白色（輝度200〜255）ですが、背景のテクスチャやグリッド線は暗いグレー（輝度50〜100）です。
*   絶対閾値で二値化することで、背景のノイズやグリッド線を100%完全にシャットアウトし、**文字の中身が詰まったクッキリと美しい純黒の文字（白背景）**を浮かび上がらせます。「0」の穴が潰れることも100%防ぎます。

### ③ ROIクロップ領域のインテリジェント拡張 (`src/config.py` の修正)
*   **メインパラメータ数値のクロップ横幅を `95` から `115` へ拡張**（右側の数字の削れを完全に防ぎます）。
*   **個別詳細パラメータのクロップ縦幅を `40` から `50` へ拡張し、Y座標を `5px` 上へオフセット**（縦スケーリングの歪みを完全に吸収します）。
