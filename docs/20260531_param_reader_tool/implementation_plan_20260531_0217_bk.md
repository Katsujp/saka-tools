# 【サカつく2026】HTML5ブラウザペースト（通信ライフサイクルバグ修正）改修計画書

本計画は、ユーザー様よりご報告いただいた「フォーカスを当てた状態で貼り付けても反応がない」という不具合の原因を特定し、Streamlitの公式カスタムコンポーネント通信規格に完全準拠させることで、ペースト（Ctrl+V）アクションを確実に検知し、Python（Streamlit）側へ画像を100%無劣化で同期転送するための改修計画です。

## 原因分析

1. **Streamlit公式通信ライフサイクルの欠落 (最主要因)**:
   * Streamlitのカスタムコンポーネントは、単に `postMessage` で `setComponentValue` を親ウィンドウに送信するだけでは動作しません。
   * iframeロード時に、まずフロントエンド（JS）側から親フレームに対して **`streamlit:componentReady`** シグナルを送信し、初期化の疎通を確立する必要があります。
   * その後、親から **`streamlit:render`** シグナルを受信した時点で、初めてコンポーネントが「アクティブ」となり、値の送信（`setComponentValue`）やフレームの高さ調整（`setFrameHeight`）がStreamlit側に受諾されます。
   * 前回の実装ではこの `componentReady` シグナルおよび初期疎通フェーズが丸ごと欠落していたため、親のStreamlitプロセスがJavaScriptからのデータメッセージをすべて「未準備の無効なメッセージ」として無視（破棄）していました。

2. **デバッグ・ステータス情報の不足**:
   * 通信接続状況がユーザーインターフェース上で視覚的に分からなかったため、ブラウザ側でのペースト動作可否やStreamlitとの疎通の成否が判別しにくい状態でした。

---

## 対策・提案内容（解決策）

1. **公式通信プロトコル（ライフサイクル）の完全実装**:
   * `src/paste_bridge/index.html` 内のJavaScriptにおいて、ロード完了時に直ちに `streamlit:componentReady` を親フレームへ送信します。
   * 親フレームから送られてくる `streamlit:render` メッセージをイベントリスナーで待ち受け、受信した時点でフレーム高設定（`setFrameHeight`）とペーストリスナーのアタッチを実行します。

2. **ビジュアルステータス表示の追加**:
   * ペースト領域の下部に、Streamlit親プロセスとの疎通状態（`🔴 未接続 / 🟢 接続完了`）を小さくリアルタイム表示する機能を追加します。
   * これにより、ユーザーは「今、貼り付け可能な状態か」を一目で判断できるようになります。
