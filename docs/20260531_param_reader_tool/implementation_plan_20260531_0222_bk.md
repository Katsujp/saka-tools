# 【サカつく2026】クリップボード画像「表示の超引き伸ばしボケ」UIバグ解消計画書

本計画は、ユーザー様よりご報告いただいた「貼り付けた結果が低解像度（モザイク状に激しくボケる）になっている」という問題の**極めて単純でありながら致命的だった真原因**を特定し、プレビューの表示品質を劇的に改善（超高解像度・クッキリ表示）させるための改修計画です。

## 🔍 原因分析（真のバグの発見）

今回の「激しいボケ」は、クリップボードAPIやWindows OSの制限ではなく、**StreamlitのUIにおけるプレビュー画像表示ロジックの単純な設計バグ**が原因でした。

1. **メモリ上のデータ（真の解像度）**:
   * HTML5ペーストブリッジ（インライン・カスタムコンポーネント）を通じてクリップボードから取り込まれた画像データは、`st.session_state.target_images` に **「完全無劣化・超高解像度」の完璧な状態** で格納されています。

2. **表示処理のバグ（諸悪の根源）**:
   * `app.py` の 417〜419行目において、メモリ上の画像を画面に表示する際、以下のコードが実行されていました。
     ```python
     thumb = img.copy()
     thumb.thumbnail((150, 150))          # ←【原因①】画像を150x150ピクセルに極小縮小
     st.image(thumb, use_container_width=True) # ←【原因②】150x150の極小画像を、画面全体の横幅に強制超拡大レンダリング
     ```
   * プレビューが1枚だけの場合、Streamlitは画面全体の横幅（約800〜1200ピクセル）を持つ1つのカラムを生成します。
   * その巨大な表示エリアに対して、`thumbnail((150, 150))` で **150x150ピクセルにまで超縮小された極小画像** を `use_container_width=True` で強引に引き伸ばして表示していました。
   * このため、元の画像がどんなに高解像度であっても、**画面上はドットが巨大に引き伸ばされ、視覚的に激しいボケ（モザイク状態）が発生し、低解像度化しているように見えてしまっていた**のです。

---

## 🛠️ 対策・解決策

プレビュー画面での不要な「極小縮小処理」を完全に排除し、高解像度のまま美しく縮小・表示されるように修正します。

1. **`thumbnail((150, 150))` 処理の完全廃止**:
   * プレビュー表示ロジックから、画像を `150x150` に強制縮小する処理を完全に削除します。
2. **生画像の引き渡し**:
   * `st.image` に対し、メモリ上の高解像度画像 `img` を直接渡します。
   * これにより、Streamlit（ブラウザの高品質な描画エンジン）が自動的にカラム幅に合わせて、**文字の1ドットまでクッキリと読める極めて高画質な縮小レンダリング**を実行するようになります。データは無劣化のままであり、表示だけが綺麗にアジャストされます。
