# 【サカつく2026】パラメータ画面画像からの数値自動抽出ツール修正・機能追加計画

本計画は、ユーザーが「画像のOCR解析の開始」をクリックした際に処理が動かない問題を解消するための原因究明と、処理状況（ログ）を画面上に詳細かつリアルタイムに出力する機能を追加するための計画です。

---

## 原因の究明（なぜ「解析開始」を押しても動かなかったのか）

Streamlit特有のライフサイクルおよび状態保持（状態管理）の仕様に起因するバグを発見いたしました。

### Streamlitの「再実行（Rerun）によるローカル変数のリセット」問題
1. **クリップボード読込時**: ユーザーが「📋 クリップボードから画像を読み込む」ボタンをクリックした際、画像オブジェクトが正常に取得され、一時的なローカル変数 `target_images = [("Clipboard_Image", pasted_img)]` に追加されます。この時、画面上に「画像のOCR解析を開始」ボタンが描画されます（添付画像の状態です）。
2. **解析開始ボタンクリック時（バグ発生）**: ユーザーが「🚀 画像のOCR解析を開始」ボタンをクリックすると、Streamlitはインタラクションを検知して**スクリプトを最上部（1行目）から「再実行」します。**
3. **データの消失**: 再実行が走るため、スクリプトの最初でローカル変数 `target_images = []` が実行され、**メモリ上にあった画像データが完全に消去（クリア）されます。**
4. **処理の不発**: この再実行ループにおいて、「画像のOCR解析を開始」ボタンは押されたものの、対象となる `target_images` は空 `[]` と判定されるため、解析ループ（`for`）が一切実行されず、初期状態の画面に一瞬でリセットされていました。

---

## 修正および機能追加の仕様

上記のバグを完全に解消し、処理状況を詳細に可視化する機能を追加します。

### ① 画像データのセッション状態（session_state）への保存（バグの解消）
取得した画像データを Streamlit のセッション状態（`st.session_state.target_images`）で保持するように修正します。
- スクリプトが再実行されても画像データは永続的に保持されます。
- 解析ボタンが押された際、セッション内から画像を取り出して確実に解析を実行します。

### ② 処理状況（ステータスログ）のリアルタイム詳細出力機能の追加（新規機能）
OCRの解析プロセスが進行する様子を、ユーザーが画面上で一目で把握できるよう、**「処理状況ステータスログ（ターミナル風デザイン）」**を追加します。

Streamlitの `st.status` および `st.empty` コポーネントを使用し、以下の進捗・詳細な処理ステップを画面上にリアルタイムでテキスト追記出力します。

#### 【出力されるログ情報の設計】
- `[INFO] クリップボードから画像オブジェクト(PIL.Image)の取得に成功しました。`
- `[INFO] 画像解析タスクを開始します (対象画像: 1枚)`
- `[PROCESS] 1. 画像の標準化リサイズ処理を実行中 (基準アスペクト比 16:9 - 1920x1080 に正規化)...`
- `[PROCESS] 2. OpenCVによるパラメータ領域 (ROI) のクロップ切り出しを開始...`
- `[PROCESS] 3. 切り出し画像の前処理 (グレースケール化、拡大、適応的二値化) を適用中...`
- `[PROCESS] 4. EasyOCRによる文字・数値の認識とテキスト抽出を実行中 (初回はモデルロードのため数秒要します)...`
- `[PROCESS] 5. 抽出テキストの正規化と数値パース (選手名、総合力、メイン、個別17項目) が完了...`
- `[SUCCESS] 6. [選手名: Nico Williams, 総合力: 6739] のパラメータデータの復元に成功しました！`
- `[SUCCESS] すべての解析タスクが正常終了しました。`

※万が一、解析中に例外エラーが発生した場合は、その詳細なエラー内容（Exception メッセージ）をログの中に赤文字で出力し、ユーザーが原因をその場で把握できるようにします。
