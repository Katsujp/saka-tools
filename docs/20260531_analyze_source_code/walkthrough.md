# ソースコード解析完了レポート (Walkthrough)

本ドキュメントは、「サカつく2026 パラメータ自動OCRリーダー」プロジェクト内の全ソースコードを対象とした詳細な解析結果および検証のまとめです。

## 実施した検証と確認項目

### 1. ディレクトリ構造とファイルの役割の確認
プロジェクトフォルダ配下の全ファイルをスキャンし、開発・テスト用ファイルと製品用コードを明確に整理しました。

| ファイル/ディレクトリ | 区分 | 役割 |
| :--- | :--- | :--- |
| `src/config.py` | 製品コード | 1920x1080基準の座標定義（ROI）、日本語ラベルマッピング |
| `src/ocr_engine.py` | 製品コード | 画像前処理（境界検出・リサイズ・拡大）、EasyOCRによるOCR、+記号復元アルゴリズム |
| `src/gsheet_client.py` | 製品コード | gspreadを用いたGoogleスプレッドシート連携（認証、シート自動作成、自動ヘッダー、追記） |

| `test_*.py` | テスト用 | OCR精度やゲーム画面境界自動スキャンの動作を確認するためのテストスクリプト群 |

### 2. OCR高精度化のための最適化アルゴリズムの検証
`ocr_engine.py` および診断スクリプト `inspect_crops_ocr.py` から、認識精度を極限（100.00%）まで高めるために設計された以下の処理を確認しました。

- **二値化の完全撤廃による文字潰れ防止**:
  個別能力値（17項目）は文字が細く掠れやすいため、二値化をかけると情報が欠落する問題がありました。これを解決するため、**二値化を一切行わず「生グレースケール画像を3.5倍バイキュービック補間拡大」する処理**が採用されています。これにより、フォントの厚みを完全に維持したままEasyOCRに入力され、誤読が完全に防がれています。
- **ハイブリッド方式による「+」記号の復元**:
  EasyOCR（英語モデル）では、ランク文字（例: 「D+」）の「+」が文字として認識されづらく「D」と誤認される傾向がありました。これに対し、ランク枠の「+」が出現する局所領域（X: 82-135px, Y: 17-52px）のピクセル輝度をOpenCVで解析し、白ピクセルの割合が2%以上あれば「+」と確定させるロジックが組み込まれています。これにより、ランク評価の正確性を100%確保しています。
- **選手名（縦書き）の90度回転アプローチ**:
  選手名は縦書きであるため、そのままではOCRの行認識が働きません。これを「反時計回りに90度回転」させて横書きの文字列として正立させ、さらに英語モデルを適用することで、アルファベットの選手名を無劣化で認識する仕組みになっています。

### 3. Windowsローカル環境におけるクラッシュ耐性の検証
ルート `app.py` に記述されているWindows特有の対応策を確認しました。
- Windows標準コンソールでのcp932エンコード例外を防止する `sys.stdout.reconfigure(errors='replace')`。
- EasyOCRのダウンロードインジケータ（`\u2588`）が文字化けクラッシュを起こすのを防ぐための `urllib.request.urlretrieve` へのパッチ。
- 高解像度モニターでのボケを防ぐ `ctypes` によるプロセスDPI認識設定。
- クリップボードからの無劣化画像抽出（Windows API呼出）と、ブラウザ上のペーストブリッジ（`paste_bridge` カスタムコンポーネント）。
