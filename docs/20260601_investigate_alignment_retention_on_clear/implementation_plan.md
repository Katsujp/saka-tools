# 画像クリア時の読取り設定保持に関する動作検証と調査報告

## 結論
個別クリアボタンをクリックして画像を削除した場合でも、**「読取りエリアの設定や有効項目の設定など（アライメント設定）は、完全に保持されたまま新しい画像へ引き継がれます。」**

したがって、本件に関しては追加のコード修正や変更を一切行う必要はなく、すでに既存のシステム設計によって完璧にサポートされております。

---

## 内部の連携・保持メカニズムの解説

なぜ設定が消えずに残り、新しい画像に引き継がれるのか、システム内の二段階のデータ保持フローを解説します。

### 1. Streamlitセッション状態（Python側）での永続的な維持
- ユーザーが個別クリアボタンを押して画像がすべて消えると、プレビューHUD自体は画面上から一旦非表示（スキップ）になります。
- しかし、スライダー等で調整されたりファイルからロードされた各設定パラメータ（`global_scale_x`、`group_offsets`、`active_items` など）は、Pythonの `st.session_state`（セッションメモリ）に格納されており、**`st.rerun()` を実行しても一切リセットされずに保持され続けます**。

### 2. Canvas HUD再レンダリング時（JavaScript側）の初期値の同期
- ユーザーが新しい画像を再びペースト／選択した瞬間、プレビューHUDコンポーネントが再描画されます。
- この描画開始のタイミングで、`app.py` から `fitting_hud` コンポーネントに対し、**セッションメモリに保持されているすべての最新調整パラメータ（位置・幅・高さ・チェック項目）が引数（args）としてダイレクトに引き渡されます**。
- `fitting_hud/index.html`（JS側）では、`streamlit:render` メッセージの受信処理において、受け取ったアライメント引数を自動でスライダーの現在値や Canvas の矩形描画へ適用・復元するロジックが 100% 確実に動作します。

## ユーザー様へのご案内と検証プラン

### 検証手順
設定が正しく保持・引き継がれていることを以下の手順で簡単にご確認いただけます。

1. **初期ペースト**: 1枚目の画像をペーストして、プレビュー画面を表示させます。
2. **アライメント調整**: スライダーを操作して「全体 X シフト」を `50 px` 程度に動かすか、いくつかの「読み取り有効項目」のチェックを外します。
3. **個別クリア**: 「選択中の画像をクリアする」ボタンをクリックします。
   - この時点で画像リストが空になり、プレビュー画面が一時的に非表示になります（設定パラメータはメモリ内で待機しています）。
4. **再ペースト（引き継ぎの確認）**: 同じ画像、あるいは別の2枚目の画像をペーストします。
   - 再びプレビューHUDが表示された際、**スライダーが `50 px` を指したままであり、チェックを外した項目も外れた状態（前回の設定）がそのまま維持されていること**が確認できます。

### 保持される設定範囲
- 全体アライメント（X/Yシフト、X/Yスケール）
- グループ別アライメント（SHO/PAS/DRBなどのグループ全体の枠線調整値）
- 個別詳細パラメータアライメント（突破力や決定力などの1px単位の個別調整値）
- 読み取り有効項目チェックリスト（ON/OFF設定）
- ロール設定（FP / GK モード）

上記の通り、アライメント設定の引き継ぎ能力はすでに実装されておりますので、どうぞ安心してご利用ください。
