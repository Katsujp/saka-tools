# UI/UX改善実装計画書（ペースト領域削減・セパレータ改善・スライダーステップボタン追加）

本計画書は、以下の3つのUI/UX改善要求に基づき、アプリケーションの操作性とデザインを向上させるための実装計画です。

1. **Android向け「長押しペースト」領域の削除**: クリップボードAPI経由のペーストが正常稼働するようになったため、不要となった長押しエリアを完全削除し、コンポーネントの高さをコンパクト化して無駄な余白を削減します。
2. **冗長なグレー四角セパレータの改善**: 各項目の間に生じている空のマークダウンカードによる「グレーの角丸長方形」を排除し、スッキリとした4pxの洗練された境界線（セパレータ）に置き換えます。
3. **スライダーの微調整用ステップボタンの追加**: スマホなどのタッチ操作時における調整の難しさを解消するため、すべてのスライダーの左右に `1`（またはステップ値 `0.01`）ずつ増減できるボタンを追加します。ただし、PC等でのキーボード操作時にフォーカス移動（Tabキー）の邪魔にならないよう、`tabindex="-1"` を指定し、スライダー本体にのみフォーカスが当たる現在の優秀なキーボードUXを維持します。

## 原因・背景
- **ペースト領域**: クリップボードAPIの安定稼働により、補助的だった「長押しエリア」が不要となり、縦方向の占有面積を減らすことで操作画面をよりスッキリさせるため。
- **セパレータ**: `app.py` における `st.markdown('<div class="apple-card">', ...)` の単体呼び出しにより、Streamlit側で空のコンテナが角丸のグレー長方形としてレンダリングされてしまい、冗長なセパレータに見えていたため。
- **スライダー**: タッチデバイスでのドラッグ微調整が難しく、`+1` / `-1` 単位の確実なタップ微調整手段が強く望まれたため。

## ユーザー確認事項
> [!IMPORTANT]
> スライダー左右の増減ボタンは、PC等のTabキーでのフォーカス移動から完全に除外（`tabindex="-1"`）し、スライダー本体にのみフォーカスが当たる設計とします。これにより、従来のキーボード操作性を100%維持します。

## 提案する変更内容

### ① ペーストブリッジの軽量化
#### [MODIFY] [paste_bridge/index.html](file:///d:/User%20Files/Masashi/HOME/repos/saka-tools/src/paste_bridge/index.html)
- `paste-area` (長押しエリア) のHTML、CSSスタイル、およびJS上のイベントリスナー（`click`, `paste`, `onload` 等でのplaceholder書き換え処理）を完全削除。
- `#paste-container` の高さを `160px` からボタンが快適に収まる `60px` 程度に削減。
- JS側の `sendMessageToStreamlit("streamlit:setFrameHeight", { height: 60 });` に高さを修正。

### ② グレーの四角セパレータを4pxの線に置換
#### [MODIFY] [app.py](file:///d:/User%20Files/Masashi/HOME/repos/saka-tools/app.py)
- 各セクションを囲もうとして余計な空の角丸四角形を生成してしまっている `st.markdown('<div class="apple-card">', ...)` および `st.markdown('</div>', ...)` をすべて削除。
- 各項目の区切りとして、スッキリとした4pxのスタイリッシュな境界線 `st.markdown('<hr style="border: none; height: 4px; background-color: #3a3a3c; margin: 28px 0; border-radius: 2px;">', unsafe_allow_html=True)` に置き換えます。

### ③ スライダーへの左右ステップ増減ボタンの配置
#### [MODIFY] [fitting_hud/index.html](file:///d:/User%20Files/Masashi/HOME/repos/saka-tools/src/fitting_hud/index.html)
- CSSにステップボタン（`.step-btn`）のスタイル（Apple純正のダークトーン、角丸、ホバーアニメーション）を追加。
- ボタンに `tabindex="-1"` を付与し、キーボードフォーカス移動の対象外に設定。
- スライダーコンテナ `.slider-container` の中で、スライダーの左右に `−` と `+` のボタンを配置。
- **全体アライメント用**: JavaScriptに関数 `stepParam(key, direction)` を実装。
- **グループ調整用**: JavaScriptに関数 `stepGroupParam(grp, type, direction, elementId)` を実装。
- **個別微調整用**: JavaScriptに関数 `stepIndivParam(item, type, direction, elementId)` を実装。
- 動的生成部分（グループおよび個別）のテンプレートリテラルを書き換え、左右ボタンをスライダーとセットで生成するように統合。

## 検証計画

### 自動・手動テスト
1. **ペースト領域**:
   - アプリ起動後、ロードパネルが薄くなり、長押しエリアが綺麗に消失していることを確認。
   - クリップボード貼り付けボタン、およびファイル選択ボタンが正常に動作することを確認。
2. **セパレータ**:
   - 各セクションの間に存在していた「分厚いグレーの四角形」が消え、4pxのスタイリッシュな細いラインに代わっていることを画面全体で確認。
3. **ステップボタン**:
   - HUD調整パネル内のすべてのスライダー（全体、グループ、個別）の左右に、`−` と `+` ボタンが綺麗に並んでいることを確認。
   - 各ボタンをクリック/タップしたとき、シフト値が `1`、スケール値が `0.01` ずつ正確に増減し、Canvas上の枠線がリアルタイムに追従することを確認.
   - PCのTabキーを連打してフォーカスを移動させたとき、増減ボタンはスキップされ、スライダー本体にのみフォーカスが当たることを検証。
