## 🛠️ 実施した修正内容

### 1. `app.py` の修正
*   **コンポーネント引数による画像データの直接伝送への統合**:
    `fitting_hud` を呼び出す際、引数に `image_base64=image_uri` を直接追加しました。これにより、Streamlit公式の双方向コンポーネント仕様に基づき、画像切り替えやペーストのライフサイクルと100%同期して安全に画像が伝送されます。
    不要となった `if hud_response is None:` 内および `resp_type == "component_loaded"` 時の一時的な `postMessage` スクリプト送信処理は完全に撤廃しました。
*   **OCR解析の二重実行・無限再実行ループ防止ガードの実装**:
    セッション状態に `ocr_run_completed` フラグを導入しました。
    「選択座標で解析を実行」ボタンがクリックされた際、このフラグが `False` の場合のみ実行し、完了後に `True` に設定します。
    ユーザーがスライダーを操作（`update_state`）するなどの次のアクションを起こした時点で自動的に `False` にリセットされ、次の解析が許可されます。これにより、解析結果表示後に他のUI操作を行った際の意図しない二重解析を完全に封殺しました。

### 2. `src/fitting_hud/index.html` の修正
*   **Streamlit公式のメッセージング（`streamlit:render`）への完全移行**:
    `streamlit:render` イベントをメッセージリスナーで捕捉し、引数 `payload.args.image_base64` から直接画像をロードするよう更新しました。画像データが前回と異なる場合のみ `onload` を走らせるため、プレビューの無駄なチラつきも一切発生しません（後方互換性として従来の `init_image` も維持）。
*   **動的スライダーのイベント同期バグの修正**:
    動的に生成される「グループ一括調整」および「項目別個別微調整」のスライダーに対し、`input` タグ自体に `onchange="notifyStateChange()"` を明示的に付与しました。これにより、ドラッグ中（`oninput`）はCanvasが超高速で追従し、ドラッグを離した瞬間（`onchange`）にPython側にすべての最新座標が完璧に同期されます。
*   **【追加修正】グループ調整スライダーの再描画時値リセットおよび同期漏れの完全封殺**:
    HTML側で動的生成される「グループ一括調整」スライダーが、Streamlitのリランによる逆同期メッセージ受信時に初期値（`0 px`, `1.00 x`）にリセットされていた深刻な表示不整合バグを究明し、`setupGroupSliders()` 内で `state.group_offsets` / `state.group_scales` からの現在値を `value` 属性とテキスト表示エリアに正しく動的バインドするよう修正しました。また、グループ・個別アライメントパラメータが変化した場合のみ、差分検知（`JSON.stringify`比較）を行って対象UIを極小範囲で再描画・同期する最適化を施しました。これによってチラつきを一切発生させず、完全にシームレスな逆同期を実現しました。
*   **GK/FPロール切り替え時の座標パラメータ相互引き継ぎの実装**:
    ロール切り替えの際、対応関係にある個別項目（例：「タックル」⇄「セービング」など）のオフセットおよびスケール値を、破棄せずに自動でコピーして引き継ぐマッピング移行ロジックを追加しました。また、生成される個別スライダーの初期位置（`value`属性）にも引き継がれた現在の値が正確に反映されるため、切り替え時に再調整を強いられるストレスを完全に解消しました。
*   **Iframe自体のスクロールバーの封殺**:
    HTMLの `body` CSSスタイルに `overflow: hidden !important;` を適用し、ブラウザズームやOSの表示スケール変更時に発生しうる「不格好な二重スクロールバー」の発生を完全に防止しました。
