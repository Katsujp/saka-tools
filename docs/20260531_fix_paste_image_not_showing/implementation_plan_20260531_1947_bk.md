## 🚨 原因究明およびゼロベースレビュー結果 (バグ診断)

### 1. ペーストした画像が表示されないバグの根本原因
- 従来の `app.py` では、コンポーネントロード時に `window.parent.postMessage` を用いて画像データをHTML側に送信していましたが、その処理が `if hud_response is None:` という限定された条件ブロック内にありました。
- Streamlitの仕様上、コンポーネントが一度でも親（Python）に状態を送信すると、`hud_response` は `None` ではなく「前回の返り値データ」を返し続けるため、新しく画像をペーストした際に**画像送信用のJavaScriptが一切実行されなくなり、HTML側に画像が届かなくなっていました**。これが画像が真っ黒になる原因です。

### 2. 【想定外の動作・危険要素1】動的に生成されたグループ・個別調整スライダーのイベントリスナー喪失
- **原因**: 
  HTML側で「グループ一括調整」や「項目別個別微調整」のスライダーはJavaScriptで動的に生成されます。しかし、Streamlitへ最新の座標を同期させる `change` イベントリスナー（`notifyStateChange`の紐づけ）の登録処理が、初期ロード時の静的要素（全体調整スライダーのみ）にしか行われていません。
- **想定外の動作**: 
  全体調整スライダーを動かした時は値がPython側に同期されますが、**グループ別調整や個別微調整のスライダーを操作しても、その座標がPython側（Streamlit）に全く同期されない**ため、OCR実行時に調整結果が反映されないという深刻な不具合が生じています。

### 3. 【想定外の動作・危険要素2】解析完了時・他UI操作時の「OCR解析無限再実行ループ・二重実行」
- **原因**: 
  JavaScript側で「選択座標で解析を実行」ボタンを押すと、`sendMessage("trigger_analysis", {})` が走り、Python側の `hud_response` の `resp_type` に `"trigger_analysis"` がセットされます。
  しかし、OCRの解析処理が完了した後、またはユーザーが他のUI操作（例えば「データテーブルのクリア」や「スプレッドシートへエクスポート」などのボタンを押した際）によりStreamlitが再実行された際、**`hud_response` は前回の値を保持し続けるため、再び `"trigger_analysis"` と判定されてしまい、意図しないタイミングでOCRが二重に再実行される**、あるいは無限ループに陥るリスクがあります。

### 4. 【想定外の動作・危険要素3】GK/FP切り替え時における「個別スライダーの勝手なリセット」
- **原因**: 
  ロール切り替え時に、個別微調整パラメータ（`state.individual_offsets` など）の初期化処理が毎回走ってしまうため、以前ユーザーがスライダーで苦労して合わせた調整値がリセットされてしまいます。
- **想定外の動作**: 
  GK/FPを切り替えた瞬間に個別スライダーの値が初期値（`0 px`, `1.00 x`）に勝手に戻ってしまい、ユーザーが再調整を強いられます。対応関係にある項目（例：「タックル」⇄「セービング」）の値は引き継がれるべきです。

### 5. 【想定外の動作・危険要素4】Iframe自体の二重スクロールバーの出現リスク
- **原因**: 
  Iframe内部の HTML で `body` のスタイルに `overflow-x: hidden;` のみが指定されており、`overflow-y` については無指定になっています。ブラウザのズーム倍率やOSのスケーリングによっては、Iframeの高さが `720px` を超えてしまい、不格好な二重スクロールバーが表示されるリスクがあります。

## 🛠️ 提案する具体的な変更設計 (承認後に実施)

### 1. `app.py` の修正計画

*   **コンポーネント引数による画像データの直接伝送**:
    `fitting_hud` の呼び出し時に、引数として `image_base64=image_uri` を直接渡すように統合します。
    `if hud_response is None:` 内で行っていた `components.html` 経由のスクリプト送信処理は完全に削除します。
    ```python
    hud_response = fitting_hud(
        key="fitting_hud_instance",
        image_base64=image_uri,  # 標準引数として安全に引き渡し！
        default_rois=DEFAULT_ROIS,
        groups=GROUPS,
        height=720
    )
    ```

*   **OCR二重再実行ガード（デバウンス・ガードロック）の追加**:
    一度OCR解析を実行したら、セッション状態（`st.session_state`）を用いて実行フラグを管理し、トリガーが1回限りの実行で終了するようガードロジックを追加します。

### 2. `src/fitting_hud/index.html` の修正計画

*   **Streamlit公式のレンダリングイベントへの移行**:
    `streamlit:render` メッセージを受信するハンドラを実装し、渡された引数 `args.image_base64` から直接画像をロードするように更新します。
    ```javascript
    window.addEventListener("message", (event) => {
        const payload = event.data;
        if (payload.type === "streamlit:render") {
            const args = payload.args;
            if (!args) return;
            
            const imgBase64 = args.image_base64;
            if (imgBase64 && imgBase64 !== bgImage.src) {
                bgImage.src = imgBase64;
                bgImage.onload = function() {
                    imageLoaded = true;
                    redrawHUD();
                };
            }
        }
    });
    ```

*   **動的スライダーへの `change` イベントリスナー適用**:
    動的生成されるスライダーのHTML要素に対し、明示的に `onchange="notifyStateChange()"` を付与することで、ドラッグ終了時に確実に最新の全座標がPython側に同期されるように修正します。

*   **GK/FP切り替え時のパラメータ引き継ぎ**:
    ロール切り替え時、「タックル」⇄「セービング」などの対応項目について、以前のスライダー調整値を破棄せず相互にコピーして引き継ぐロジックを実装します。

*   **Iframe自体のスクロールバーを完全に排除**:
    HTMLの `body` スタイルに `overflow: hidden !important;` を適用し、二重スクロールバーの発生を100%封殺します。
