## 🛠️ 実施した修正内容

### 1. `app.py` の修正・堅牢化
* **インポートキャッシュを強制破棄するOCRエンジン強制再ロードの実装**:
  Pythonの `sys.modules` キャッシュにより、コードを書き換えても古いクラス定義（`is_preprocessed` を持たないもの）が使われ続けていた問題を完全に解消するため、`importlib.reload` を導入しました。
  引数の不整合を動的シグネチャ検証（`inspect.signature`）で自動検知した際、キャッシュモジュール自体を強制的に破棄して最新の `src/ocr_engine.py` ファイルから最新定義をリロードするガードを実装しました。これにより、100%確実に最新の `SakatsukuOCREngine` クラスがインスタンス化され、TypeErrorによるOCR解析のクラッシュを永久に解決しました。

### 2. `src/fitting_hud/index.html` の修正・堅牢化
* **falsy（null / undefined）を完全に排除する真値チェックへの移行**:
  逆同期オブジェクトが `null` の場合に `args.group_offsets !== undefined` などの脆弱な条件分岐をすり抜けて `JSON.parse(JSON.stringify(null))` ➔ `null` になり、その後のプロパティ参照で `TypeError: Cannot read properties of null` が発生してJavaScriptスレッドが完全にクラッシュ（画面がフリーズ・グレーアウト）していた問題を解消しました。
  `!== undefined` の代わりに、JavaScriptの強力な真値検証（falsy排除）`if (args.group_offsets)` などに移行し、値が確実に存在する場合のみプロパティアクセスを実行するよう徹底して例外発生を100%封殺しました。
* **Iframeメッセージハンドラ全体の try-catch 保護の追加**:
  何らかの予期せぬブラウザ例外が発生した場合でも、Iframe全体の描画クラッシュ（画面のグレーアウト）を完全に防ぎ、安全に動作を継続できるように、メッセージハンドラ（`streamlit:render` 受信イベント）全体を try-catch でセキュア保護しました。
