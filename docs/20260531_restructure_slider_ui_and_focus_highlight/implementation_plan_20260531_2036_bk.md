# UIスライダーのグループ再構成およびキーボードフォーカス強調表示の実装計画

本ドキュメントは、アライメント調整画面（Canvas HUD）の右側コントロールパネルにおいて、従来の「グループ一括調整（案A）」と「項目別個別微調整（案B）」の物理的な分離構成を廃止し、各カテゴリ（グループ）ごとに「全体調整」と「個別調整」を美しく統合し、さらにキーボード操作を快適にするフォーカス強調表示を実装するための計画書です。

---

## 原因・現状の課題

1. **操作の行き来が発生するUI構造**: 
   これまでは「グループ一括調整」と「個別微調整」が離れた別々のアコーディオンに配置されていたため、同じカテゴリー（例：SHO数値と決定力）を調整する際に、ユーザーがアコーディオン間を上下に行き来してスライダーを操作する必要があり、操作効率が低下していました。
2. **キーボード操作時のフォーカス視認性の不足**:
   キーボード（`Tab`キーなど）でスライダーにフォーカスを当てて微調整（左右の矢印キーなど）する際、現在どのスライダーが選択状態にあるのかが視覚的に非常に分かりづらく、直感的な操作が困難でした。

---

## ユーザーレビューが必要な内容

> [!NOTE]
> - 「全体アライメント (Global)」は、画面全体を統一して調整するマスターアライメントであるため、アコーディオンの対象外として最上部に残します。
> - 各グループ内の個別調整項目は、既存の「読み取り有効項目」のチェックボックス（ON/OFF）と連動し、OFFになった項目は動的に非表示（`display: none`）になります。これによりアコーディオン内のレイアウトが自動的に最適化されます。

## 提案する具体的な変更設計

### 1. 右側コントロールパネルのスライダー再構成 (グループ別完全統合)
従来の「グループ一括調整」と「項目別個別微調整」の2大アコーディオンを廃止し、**各カテゴリ（グループ）ごとに統合されたアコーディオン**に集約します。

* **カテゴリ別の構成定義**:
  - **「総合力」アコーディオン (`overall`)**:
    - グループ全体の調整は不要なため、個別項目 **「総合力」** のスライダー（X/Yシフト、X/Yスケール）のみを配置します。
  - **「カテゴリー数値」アコーディオン (`category`)**:
    - **カテゴリー数値 (全体)** の調整スライダー（X/Yシフト、X/Yスケール）を最上部に配置。
    - その下に、属する個別項目（**SHO数値, PAS数値, DRB数値, DEF数値, PHY数値, SPD数値**）の個別微調整スライダーを配置。
  - **「SHO」アコーディオン (`sho`)**:
    - **SHO (全体)** の調整スライダーを最上部に配置。
    - その下に、属する個別項目（**決定力, キック力, 冷静さ**）の個別微調整スライダーを配置。
  - **「PAS」アコーディオン (`pas`)**:
    - **PAS (全体)** の調整スライダーを最上部に配置。
    - その下に、属する個別項目（**ショートパス, ロングパス, キック精度**）の個別微調整スライダーを配置。
  - **「DRB」アコーディオン (`drb`)**:
    - **DRB (全体)** の調整スライダーを最上部に配置。
    - その下に、属する個別項目（**突破力, キープ力, ボールタッチ**）の個別微調整スライダーを配置。
  - **「DEF」アコーディオン (`def`)**:
    - **DEF (全体)** の調整スライダーを最上部に配置.
    - その下に、属する個別項目（**タックル/セービング, パスカット/反応速度, マーク/1対1**）の個別微調整スライダーを配置。※GK時はGK用ラベルに動的変更。
  - **「PHY」アコーディオン (`phy`)**:
    - **PHY (全体)** の調整スライダーを最上部に配置。
    - その下に、属する個別項目（**ジャンプ, コンタクト, スタミナ**）の個別微調整スライダーを配置。
  - **「SPD」アコーディオン (`spd`)**:
    - **SPD (全体)** の調整スライダーを最上部に配置。
    - その下に、属する個別項目（**走力, 敏捷性**）の個別微調整スライダーを配置。

* **JavaScript側でのUI動的生成ロジックの刷新 (`src/fitting_hud/index.html`)**:
  - HTML側から `accGroups` および `accIndiv` を削除し、代わりにアライメント用アコーディオンを動的に挿入するための親コンテナ `<div id="alignmentContainer"></div>` を追加します。
  - JavaScript側で `GROUPS` オブジェクトに基づいて、カテゴリ別のアコーディオンとスライダー群を動的に一括構築する `setupAlignmentUI()` 関数を実装します。
  - 各アコーディオンは、ユーザーが直感的に開閉できるようにし、初期状態では「総合力」と「カテゴリー数値」を開いた状態、他を閉じた状態など、見やすさを考慮して適切に制御します。

### 2. キーボード操作のためのフォーカス強調スタイリングの実装
* **CSSによるフォーカス強調 (`src/fitting_hud/index.html` の Style)**:
  `Tab` キーやクリックによって現在フォーカスが当たっているスライダー（`input[type="range"]`）が直感的に識別できるよう、洗練されたApple Pro Blueカラーを用いた強調スタイリングを追加します。
  ```css
  /* スライダーフォーカス時のシャープな強調表示 */
  .apple-slider:focus {
      background: var(--accent-color) !important;
      outline: none;
  }
  
  .apple-slider:focus::-webkit-slider-thumb {
      background: #359aff !important; /* フォーカス時はつまみをより鮮やかな青に */
      box-shadow: 0 0 8px rgba(10, 132, 255, 0.8), 0 2px 6px rgba(0, 0, 0, 0.4);
      transform: scale(1.2);
  }
  ```

## Verification Plan

### 手動・UI/UX検証
1. 構文エラーがないか `python -m py_compile app.py` を実行して確認します。
2. アプリケーションを起動し、右側のコントロールパネルに「総合力」「カテゴリー数値」「SHO」「PAS」「DRB」「DEF」「PHY」「SPD」の各グループが美しいアコーディオンカードとして配置されていることを確認します。
3. **「総合力」アコーディオンを開き、中に「総合力」のみの調整スライダーが存在すること（全体調整がないこと）を確認します。**
4. **「SHO」などのカテゴリのアコーディオンを開き、最上部に「SHO (全体)」、その下に「決定力」「キック力」「冷静さ」の個別スライダーがまとまって配置されていることを確認します。**
5. 「読み取り有効項目」のチェックボックスで項目をON/OFFした際、該当するアコーディオン内の個別スライダー行が動的に表示/非表示（`display: none`）に切り替わり、アコーディオンの高さが自動調整されることを確認します。
6. `Tab` キーを押してスライダー間をフォーカス移動した際、現在選択されているスライダーの背景やつまみの色が**美しい青色にビビッドに変化し、キーボード（矢印キー）でどのパラメータが動くかが完璧に視認できること**を確認します。
