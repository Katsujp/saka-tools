# 修正内容の確認 (Walkthrough): Streamlit Cloud デプロイ環境の EasyOCR 起動クラッシュ修正

本ドキュメントは、アプリケーションを Web（Streamlit Cloud）へデプロイした際、EasyOCRのモデル自動ダウンロードにおいて `temp.zip` の `FileNotFoundError` でクラッシュしていた致命的なバグの原因分析および修正結果についてまとめた報告書です。

---

## 1. 実施した修正・追加内容

### ① EasyOCRモデル保存先ディレクトリの一時フォルダ（`/tmp`）への明示的避難
- **対象ファイル**: [src/ocr_engine.py](file:///d:/User%20Files/Masashi/HOME/repos/saka-tools/src/ocr_engine.py)
- **修正内容**:
  - デフォルトで `~/.EasyOCR/model/`（ユーザーホームディレクトリ配下）にモデルを自動保存しようとし、Streamlit Cloudのコンテナ Linux 環境特有の書き込み・ディスク権限制限によって `temp.zip` の解凍エラーを吐いていた仕様を改善しました。
  - OSに依存せず100%確実にファイル書き込み権限が許可されているシステム一時ディレクトリ（Linux環境であれば `/tmp/easyocr_models`）を `tempfile.gettempdir()` より自動取得・生成。
  - `easyocr.Reader` を初期化する際、引数 **`model_storage_dir`** にこの安全な一時ディレクトリパスを明示的に指定して起動するロジックに改修。これにより、デプロイ先環境のホームディレクトリのパーミッション制限を完全にバイパスし、起動およびモデルダウンロードが確実に成功する堅牢な構造へと修正しました。

### ② Windows固有最適化・バグ回避パッチのOS限定ガード
- **対象ファイル**: [app.py](file:///d:/User%20Files/Masashi/HOME/repos/saka-tools/app.py)
- **修正内容**:
  - DPI Aware設定および cp932 エンコード文字化けによる Windows 起動時フリーズを防ぐための `urlretrieve` パッチ処理の実行を、**`platform.system() == "Windows"`** の場合のみに厳密に制限しました。
  - これにより、Streamlit Cloud (コンテナLinux環境) 上では不要な割り込みパッチが完全にバイパスされ、Python標準ライブラリのネイティブかつクリーンな通信・ファイル書き込み処理が安全に実行されます。
