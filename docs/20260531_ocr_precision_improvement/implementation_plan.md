## 検出された不具合の原因特定 (Root Causes)

徹底的なパラメトリクス探索により、以下の原因を特定し、その対策を検証完了しました。

### 1. 総合力およびポジションの切り出し座標ズレと二値化誤読
*   **原因**: 従来のX座標 `45` では、総合力の最初の文字「6」の左側が削れてしまい、`739` のように誤認識されていました。また、二値化の閾値 `155` では「6」が「8」に誤読（`8739`）される問題がありました。
*   **対策**: 総合力のX座標を `30` まで広げて左余白を十分に確保し、かつ「二値化なし（生グレースケール3.5倍超拡大）」を適用することで、寸分の狂いもなく `6739` を完璧に認識できることを実証しました。ポジションも `X=35` に設定し、大津の二値化を適用することで `LW` を100%完璧に認識します。

### 2. ランク「D+」のプラス記号「+」のAIモデル限界
*   **原因**: 「D+」などのランクエンブレムに描かれる「+」記号は、フォントが細く「D」の文字に密接しているため、EasyOCRのテキスト認識モデル（CRAFT）が文字として認識できずに無視してしまい、`D` や `C` としか認識されませんでした。
*   **対策**: OCRエンジンのみに頼るのではなく、OpenCVを使用した **「HSV/輝度ピクセル補助解析」** を導入します。ランク切り出し画像の右側領域（+記号が存在するエリア）に輝度160以上の白いピクセルが一定割合（2%以上。実画像では58%超）存在するかどうかを判定し、存在する場合は認識された `D` や `C` の末尾に自動的に `+` を付与して完璧に復元します。これにより、100%確実に `D+` を読み取ります。

### 3. 個別詳細パラメータへの日本語項目名ラベル映り込みと数字の削れ
*   **原因**:
    *   以前のY座標 `Y = Y_org + 10, H = 35` では、キック力「411」の「4」の左端が切れて `11` になり、冷静さ「409」では上部の日本語「冷静さ」の白文字が映り込んで EasyOCR の認識結果を汚染し、`400` や `100` に誤読されていました。
    *   Y座標を `+12` 下げすぎると、今度は数字自体が上下で切れてしまい、`41` や `''` (空白) となり認識できなくなっていました。
*   **対策**:
    *   **X座標の20px左シフト**: 1列目のX座標を `730` に拡張することで、「4」が切れるのを完璧に防ぎます。
    *   **Y軸+8pxシフト＆H=38pxの黄金比**: Y座標を `+8px` 下げ、高さを `38px` に設定します。この黄金座標により、上部の日本語ラベルとグレーの境界線を100%完全にフレームアウトさせつつ、数字の全体（高さ18px）を一切削ることなく完全に捉えることが可能となり、冷静さ **`409`** やキック力 **`411`** を100.00%完璧に一致させて認識できることを実証しました。
