# 実装計画書: スライダー増減ボタン連打によるシステムクラッシュの修正 ＆ 長押し連続増減機能の追加

本計画書は、スライダーの両端の「微調整用増減ボタン」を連続クリックした際のクラッシュバグの修正に加えて、**「ボタンを押しっぱなし（長押し）にした際に数値が連続して増減する機能（オートリピート）」**を安全に実装するための設計計画をまとめたものです。

## 原因（解析の背景）
増減ボタンの連続クリックによりシステムがクラッシュする根本的な原因は、**「通信の逆同期時におけるHTMLのDOM要素の全破壊・再生成処理」**と**「Streamlitの超高速連続rerunによる過負荷」**の衝突にあります。具体的には、以下のメカニズムでクラッシュが発生しています。

1. **ボタンのクリック**: JS側の調整値が更新され、Streamlit側に同期送信されます。
2. **Streamlitのrerunと受信**: Python側で値が更新されスクリプトが再実行された結果、親からJS側に最新の調整データが届きます（逆同期）。
3. **DOMの全破壊（問題の核心）**: JS側で親から座標データを受け取った際、差異があると判定されると **`setupItemsGrid()` および `setupAlignmentUI()` が呼び出され、現在操作中のスライダー要素を含めたすべてのUI要素が一度全クリア（`innerHTML = ""`）され、一から再構築**されてしまいます。
4. **衝突とクラッシュ**: ボタンを連続クリックすると、「クリック → rerun → データ受信 → UI全破壊・再生成」というサイクルが超高速で多重ループします。操作中のボタン要素が消滅し、WebSocket通信もパンクするため、最終的にフリーズやクラッシュを引き起こします。

## 提案する修正・追加機能

DOM要素の「全破壊・再生成」を完全に廃止して値のピンポイント更新に切り替えるとともに、長押しによるオートリピートを極めて安全かつサクサク動作するプレミアムな設計で追加します。

### ① [src/fitting_hud/index.html](file:///d:/User%20Files/Masashi/HOME/repos/saka-tools/src/fitting_hud/index.html) の修正・機能追加

#### 1. DOM全破壊処理の廃止と、値のピンポイント更新の実装
- 親から `streamlit:render` 経由で逆同期メッセージが届いた際、`setupItemsGrid()`（UI全再構築）を呼び出すのを**完全に廃止**します。
- `setupItemsGrid()` の呼び出しは、「初回ロード時」または「ポジションロール（FP ↔ GK）の切り替え時」などの、**表示項目（チェックボックス）自体が物理的に変化するタイミングのみ**に厳密に制限します。
- 親からのデータ受信時には、スライダーDOM要素を直接狙い撃ちして、スライダーの `.value` およびテキストの `.innerText` のみを直接更新する同期関数 `updateAlignmentUIValues()` を実装します。これにより、調整中もボタンやフォーカスが一切消滅しなくなります。

#### 2. ボタン長押しによる「連続増減機能（オートリピート）」の実装
ボタンを押しっぱなしにした際、数値がスムーズに連続増減するオートリピート機能をJavaScriptで実装します。
- **長押しの検知**:
  - 増減ボタンの `mousedown`（およびモバイル向けの `touchstart`）イベントで、タイマーを起動します。
  - 最初の `350ms` 長押しされた場合、オートリピート状態に入り、その後 `60ms` 間隔で数値の増減ロジックを連続的に繰り返し実行します（`setInterval`）。
  - `mouseup` / `mouseleave`（および `touchend`）イベントで、すべてのタイマーを完全にクリアして増減を停止します。
- **長押し中の超安全な通信設計（最重要）**:
  - オートリピート（長押し増減）が動作している間は、Python（Streamlit）側への状態送信（`sendMessage`）を**完全に一時保留（ブロック）**します。
  - 長押し中は、**ブラウザローカルの Canvas HUD のみが増減に合わせてゼロ遅延（即座）でヌルヌルと再描画され続けます**。
  - ボタンから指を離した瞬間（`mouseup` 等でオートリピートが停止したタイミング）に、**最終的な調整値を 1回だけ確実に Python 側に同期送信**します。
  - これにより、操作中のサクサク感（ゼロ遅延）を極限まで高めつつ、Streamlitサーバーへの通信負荷を完全にゼロにし、クラッシュバグの再発を100%封殺します。

#### 3. デバウンス時間の微調整
- 連打クリック時および長押し終了時の通信負荷を最適化するため、`notifyStateChange()` のデバウンスのディレイを現在の `150ms` から `250ms` に少し緩和します。

## 検証計画

### 1. 手動ストレス長押し・連打テスト
- 各増減ボタン `[ − ]` `[ + ]` を押しっぱなし（長押し）にし、画面上の赤/青の枠線がヌルヌルとスムーズに追従することを確認します。
- 長押し中にStreamlitサーバーへ通信（rerun）が一切走らず、ボタンから指を離した瞬間にだけ 1回だけ再描画（同期）が走ることを確認します。
- ボタンを1秒間に5回以上の超高速で連続クリック（連打）し、UIがフリーズせず、フォーカスが維持されることを確認します。

### 2. 座標同期の正確性確認
- 長押し操作を止めた直後に、最終的な調整座標が Python 側の `DEFAULT_ROIS` に正確に適用され、OCR解析が正しい領域で実行されることを確認します。
