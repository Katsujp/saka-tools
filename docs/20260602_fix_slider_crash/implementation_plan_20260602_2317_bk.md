# 実装計画書: スライダー増減ボタン連打によるシステムクラッシュの修正

本計画書は、スライダーの両端に追加した「微調整用増減ボタン」を何度も連続クリックした際にシステムがフリーズ・クラッシュする致命的なバグについての原因究明結果と、それを根本から修正するための具体的なアプローチをまとめたものです。

## 原因（解析の背景）
増減ボタンの連続クリックによりシステムがクラッシュする根本的な原因は、**「通信の逆同期時におけるHTMLのDOM要素の全破壊・再生成処理」**と**「Streamlitの超高速連続rerunによる過負荷」**の衝突にあります。具体的には、以下のメカニズムでクラッシュが発生しています。

1. **増減ボタンのクリックによる状態同期送信**:
   - ボタンをクリックすると、JS側の調整値が更新され、`notifyStateChange()`（150msデバウンス）によって Streamlit 側へ `update_state` メッセージが送信されます。
2. **Streamlitのrerun実行**:
   - Python側でメッセージを受け取ると、`st.session_state` の値が更新され、Streamlit がスクリプト全体を再実行（rerun）します。
3. **親からJSへの再レンダリングシグナル（逆同期）**:
   - rerun の結果、親から最新の座標データが `streamlit:render` イベントとしてJS側に送られます。
4. **JS側でのUI全破壊・再生成（問題の核心）**:
   - JS側は、親から送られてきた `group_offsets` や `individual_offsets` などの座標値がローカル状態と異なると判断すると、**`setupItemsGrid()` および `setupAlignmentUI()` を呼び出して、コントロールパネル内のすべてのスライダー要素（DOM）を一度全削除（`innerHTML = ""`）し、一から再構築**します。
5. **クラッシュの発生**:
   - ユーザーが増減ボタンを連打（例えば 200ms 間隔で連続クリック）すると、**「クリックによって送信 → rerun → 親からデータ受信 → UI全破壊・再構築」というサイクルが超高速で多重ループ**します。
   - この結果、クリックした瞬間に操作対象のボタンを含むDOMが破壊されて消滅するため、ブラウザのフォーカスが外れ、イベントハンドラが多重登録され、最終的にブラウザのJavaScriptエンジンがハングするか、StreamlitのWebSocket通信がパンクし、システムが強制終了（接続切断）に至ります。

---

## 提案する修正内容

DOM要素の「破壊・再生成（全クリア）」を止め、値のピンポイント更新に切り替えることで、フリーズやクラッシュを100%防止し、信じられないほどスムーズでプレミアムな操作感を実現します。

### ① [src/fitting_hud/index.html](file:///d:/User%20Files/Masashi/HOME/repos/saka-tools/src/fitting_hud/index.html) の修正

1. **DOMの全破壊・再構築処理の廃止**:
   - 親から `streamlit:render` 経由でアライメント値（`global_scale`, `group`, `individual` のオフセットやスケール）の逆同期メッセージが届いた際、`setupItemsGrid()`（UI全再構築）を呼び出すのを**完全に廃止**します。
   - `setupItemsGrid()` の呼び出しは、「初回ロード時」または「ポジションロール（FP ↔ GK）の切り替え時」などの、**表示する項目（チェックボックスやスライダーの種類）自体が物理的に切り替わるタイミングのみ**に厳密に制限します。

2. **ピンポイント値更新関数 `updateAlignmentUIValues()` の新規実装**:
   - 親から新しい調整値が届いた際は、DOMを再作成するのではなく、既存のDOM要素を `document.getElementById` で狙い撃ちし、スライダーの `.value` および表示テキストの `.innerText` のみを直接書き換える軽量な同期関数を実装します。
   ```javascript
   function updateAlignmentUIValues() {
       // 全体スライダーの同期
       const sldGx = document.getElementById("sld_g_x");
       if (sldGx) sldGx.value = state.g_x;
       // ...同様にグループ、個別の既存スライダー要素をループで狙い撃ちして値のみを同期
   }
   ```
   - これにより、スライダーの微調整中にDOMが破壊されることが完全になくなり、フォーカスも外れず、極めて安定した動作になります。

3. **デバウンス時間の微調整**:
   - 連打時のStreamlitサーバー過負荷を和らげるため、デバウンスの送信ディレイを現在の `150ms` から `250ms` に少しだけ緩和します。
   - 画面上の赤/青の枠線描画（`redrawHUD()`）はボタンクリック時に**ゼロ遅延（即座）**で走るため、操作のサクサク感は一切損なわれません。

## 検証計画

### 1. 手動ストレス連打テスト
- 各種スライダーの増減ボタン `[ − ]` `[ + ]` を 1秒間に 5回以上の超高速で連続クリック（連打）し、UIがフリーズしないこと、およびフォーカスが維持されることをブラウザ上で確認します。
- Streamlit のコンソールに接続エラーや `RerunScriptException` が一切発生せず、サーバーが安定稼働し続けることを確認します。

### 2. 座標同期の正確性確認
- 連打を止めた直後に、最終的に調整されたアライメント座標が Python 側の `DEFAULT_ROIS` に正確に適用され、OCR解析が正しい領域で実行されることを確認します。
