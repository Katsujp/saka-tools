# 実装計画：Apple Pro基準のミニマリズムUIおよび超速リアルタイムCanvasフィッティングHUDへのリニューアル

本ドキュメントは、世界トップ1.0%レベルの極上かつ合理的なUI/UXデザイナーの視点に立ち、ユーザーの操作時の快適性（ゼロ遅延・完全リアルタイム追従）とApple Pro製品のような洗練されたミニマリズムデザインを具現化するための全面的な改修計画書です。

---

## 🚨 現状の問題と解決に向けた超高度デザインアプローチ

### 1. スライダー可動範囲の不足 (要件1への対策)
- **原因**: 従来のオフセット限界が小さすぎたため、アスペクト比の異なる画像やズレの大きな画像に対応できませんでした。
- **解決策**: グローバル（全体）、グループ、および個別のすべてのX/Y軸オフセットスライダーの範囲を、画像サイズを完全にカバーする **`-1920` 〜 `1920` (X軸)** および **`-1080` 〜 `1080` (Y軸)** へ大幅に拡張します。これにより、画像上のどの位置へも制約なく自由に配置することが可能になります。

### 2. スケール調整の次元拡張 (要件2への対策)
- **原因**: 全体の縦横固定スケールしか調整できなかったため、縦横比が歪んだ画像（引き伸ばされたスクリーンショットなど）に適合できませんでした。また、項目やグループごとの個別拡大縮小も不可能でした。
- **解決策**: スケール設定ができるすべての対象（全体、グループ、および個別）において、**X方向スケール（幅倍率）とY方向スケール（高さ倍率）を個別に独立して設定可能**にします。調整範囲は **`0.10` 〜 `3.00` 倍** (0.01刻み、初期値1.00) とし、いかなるアスペクト比や歪みにも完全にフィットさせます。

### 3. スライダードラッグ中の遅延・非追従問題 (要件3への対策)
- **原因**: Streamlit標準の `st.slider` は、ドラッグを離す（マウスリリース）までPythonサーバーに値が送られないため、ドラッグ中に枠線がリアルタイムで追従せず、ユーザービリティを著しく損ねていました。
- **解決策 (究極のUXエンジニアリング)**: 
  **「クライアントサイド完全リアルタイム・Canvas調整コンポーネント」**をHTML/JavaScriptで自作し、ブラウザ内で処理を完結させます。
  1920x1080に正規化した画像をBase64形式でブラウザ側へ渡し、HTML5の `<canvas>` 上でレンダリング。JavaScriptにより、スライダーをドラッグしている間、**サーバー通信を一切挟まずにミリ秒単位で（60FPS）枠線が画像の上で完全に滑らかに追従・描画**される極上のヌルヌル操作感を実現します。
  ドラッグ中もリアルタイムにズレを確認でき、ストレスフリーなフィッティング体験を提供します。

### 4. 配色・アイコンの「Appleライク」な極上リニューアル (要件4への対策)
- **原因**: 派手なネオンカラー、蛍光ミントグリーン、および多数の絵文字（⚽, 🛠️ 等）が乱立し、プロ向けの静粛な美しさが損なわれていました。
- **解決策 (Apple Pro基準の漆黒ミニマリズム)**:
  - **色数の徹底的な制限**: 漆黒（`#1c1c1e`）と深みのあるダークグレー（`#2c2c2e`）をベースとし、アクセントカラーにはAppleの純正UIで採用されている洗練された **SF Pro Blue（`#0a84ff`）** および純白（`#ffffff`）、繊細なテキストグレー（`#8e8e93`）のみを使用。
  - **ノイズ（絵文字）の100%完全排除**: タイポグラフィと空白（マージン）だけで情報のメリハリ（Hierarchy）を表現し、絵文字やダサい装飾を一切排除。まるでmacOSやiOSの「システム設定」や、Appleの「Numbers/Keynote」を触っているかのような洗練された操作体験を統一します。
  - **極細でシャープな線表現**: プレビュー枠線も、派手なネオンミントグリーンから、上品な白（`#ffffff`、線幅1px）に微小な外陰影を施すか、または極めて細いSF Blue（`#0a84ff`）で統一し、情報のインテリジェントな提示を行います。

## 📐 動的座標（ROI）算出の数学的定義

幅（W）と高さ（H）のスケール調整も完全に連動し、拡大縮小がアンカー位置（X/Y）に対して正しく働くよう、以下の積算型座標計算式を適用します。

- **総Xスケール**: $S_{total\_x} = \text{Global\_Scale\_X} \times \text{Group\_Scale\_X} \times \text{Individual\_Scale\_X}$
- **総Yスケール**: $S_{total\_y} = \text{Global\_Scale\_Y} \times \text{Group\_Scale\_Y} \times \text{Individual\_Scale\_Y}$

各項目の最終適用ROI $(X_{final}, Y_{final}, W_{final}, H_{final})$ の算出：
$$X_{final} = \text{Default\_X} \times S_{total\_x} + \text{Global\_Offset\_X} + \text{Group\_Offset\_X} + \text{Individual\_Offset\_X}$$
$$Y_{final} = \text{Default\_Y} \times S_{total\_y} + \text{Global\_Offset\_Y} + \text{Group\_Offset\_Y} + \text{Individual\_Offset\_Y}$$
$$W_{final} = \text{Default\_W} \times S_{total\_x}$$
$$H_{final} = \text{Default\_H} \times S_{total\_y}$$

## 🛠️ 主要コンポーネントの変更方針

### 1. `src/config.py`
- グループおよびデフォルトROI定義を維持。

### 2. `src/ocr_engine.py`
- 縦横独立スケールに対応するため、`calculate_dynamic_roi` メソッドを拡張し、各レベルの `(scale_x, scale_y)` と `(offset_x, offset_y)` を積算処理するロジックへ修正。
- `extract_all_parameters` についても、動的な縦横独立スケールを受け取れるように拡張。

### 3. `app.py`
- HTML5 CanvasとJavaScriptによる「リアルタイム追従型調整HUDコンポーネント」を構築し、ブラウザ内でスライダーのドラッグイベントとCanvasの即時描画を完結させます。
- コントローラー側のスライダー、FP/GK切り替え、項目ON/OFFチェックボックスなどをこのHTML内にApple純正 System Settings 瓜二つのエレガントなレイアウトで構築。
- スライダー変更完了時または「解析実行」クリック時に、JSONをPython側に受け渡し、Python側でEasyOCRによるパラメータ解析を一瞬で実行し、結果表とコピペエリアを美しく更新します。
- 配色、マージン、タイポグラフィをApple基準のミニマリズムへ統一。
