# 実装計画書: JSON設定読み込み時の上書き確認 ＆ 復元同期バグの修正

本計画書は、「スライダー等で座標や項目を変更した後にJSON設定ファイルを読み込んでも反映されない」という致命的な同期バグの原因と解決策、および「すでに変更が行われている場合に上書きの確認を求めるダイアログ」を追加するための改修設計をまとめたものです。

---

## 原因（JSON復元が反映されなかった理由）
調査の結果、「スライダー調整後にJSONを読み込んでも反映されない」という問題は、先に導入した**「非同期逆流上書き戻り防止ガード（`lastSentState`）」**が意図せず逆方向に作用してしまっていたことが原因であると判明しました。

1. **ユーザー操作時のキャッシュ保持**:
   - ユーザーがスライダーを動かした際、JS側でその最新調整値を `lastSentState` としてキャッシュします。
2. **JSONアップロード時のPython値更新**:
   - JSONファイルを読み込むと、Python（Streamlit）側でセッション状態（`st.session_state`）がJSONの値へ更新され、rerun が実行されます。
3. **逆同期データの無視（問題の核心）**:
   - 親から最新の座標データが `streamlit:render` 経由でJS側に届きます。
   - JS側は、「親から届いた値（JSONの値）」が「直前に自分が送信してキャッシュしていた値（`lastSentState`）」と異なっているため、これを「古いデータが遅れて届いた（逆流）」と誤判定し、親のデータを**無視（拒否）**してローカルキャッシュの値で強制上書きして戻していました。
   - このため、JSONファイルを読み込んでも、UIの座標が以前のスライダー調整値から全く変わらないという状態が生まれていました。

---

## 改修設計と提案内容

この競合問題を完全に解決するため、親からJS側へ「JSONが読み込まれた」という明示的なリセットシグナルを送り、JS側のキャッシュを一時的に強制破棄する仕組みを実装します。さらに、Streamlitの `st.dialog` を用いて、美しい確認モーダルを追加します。

### ① [app.py (ルート直下)](file:///d:/User%20Files/Masashi/HOME/repos/saka-tools/app.py) の改修

1. **セッション変更検知ヘルパー `is_session_modified()` の追加**:
   - セッション上の各種座標、有効項目（`active_items`）が初期状態（すべて 0、スケール 1.0、項目がデフォルト全選択）から変更されているかをチェックする関数を実装します。

2. **確認ダイアログ `st.dialog` によるモーダルの実装**:
   - 変更が行われた状態で `st.file_uploader` にファイルがアップロードされた場合、`@st.dialog("設定上書きの確認")` モーダルを表示します。
   - 「⚠️ すでに調整が行われています。設定ファイルを読み込むと現在の内容は破棄されますがよろしいですか？」と確認を求め、
     - **はい、上書きします**をクリック: JSONの内容を適用し、JS側のキャッシュを破棄させるためのワンタイムリセットID `st.session_state.restore_sync_id`（例: `"restore_172837..."`）を発行して `st.rerun()`。
     - **キャンセル**をクリック: アップローダーをクリアし、何事もなかったかのように `st.rerun()`。

3. **無条件適用のサポート**:
   - 変更が行われていない（初期状態のままの）場合は、ダイアログを挟まずに即座に設定を適用します。

4. **コンポーネントへの `restore_sync_id` 引数の追加**:
   - `fitting_hud(...)` の引数に `restore_sync_id` を引き渡します。

### ② [src/fitting_hud/index.html](file:///d:/User%20Files/Masashi/HOME/repos/saka-tools/src/fitting_hud/index.html) の改修

1. **`restore_sync_id` シグナルの受信とキャッシュ破棄**:
   - 親から送られてくる引数 `args.restore_sync_id` をJS側で監視します。
   - このIDが新しく変化したことを検知した際、JS側の **`lastSentState = null`（キャッシュ完全破棄）** を実行し、アライメント同期ガードを一時的に無効化します。
   - キャッシュが破棄されたことで、親（JSON）から届いた設定値が 100% 確実にローカルの `state` に適用され、Canvas上の枠線とコントロールパネルのスライダーが完璧に同期更新されます。

## 提案するファイル変更詳細

### 1. `app.py`
- 変更検知関数と設定適用関数の定義。

### 2. `src/fitting_hud/index.html`
- JS側の初期状態に `restore_sync_id: ""` を追加。
- `window.addEventListener("message", ...)` 内で `args.restore_sync_id` が変化したときに `lastSentState = null` に破棄するイベント処理を追加。

## 検証計画

### 1. 調整済み状態でのJSONロードと確認モーダル検証
- スライダーをいくつか適当に操作し、アライメント枠を変更します。
- その状態でアライメントJSONをアップロードした際、Streamlit画面上に「設定上書きの確認」ダイアログモーダルが出現することを確認します。
- 「キャンセル」を押した際、設定は上書きされず、アップローダーがクリアされることを確認します。
- 「はい、上書きします」を押した際、モーダルが閉じ、設定ファイルの内容が Canvas HUD の赤/青の枠線および各スライダーに100%正確に上書き適用されることを確認します。

### 2. 初期状態でのロード検証
- アプリ起動直後（またはリセット直後）、何も変更していない初期状態でJSONをアップロードした際、確認ダイアログを挟まずに即座に設定値が上書き適用されることを確認します。
